# 02 线性表

> 重点：顺序表 vs 链表、插入删除复杂度、**单链表算法设计题（双指针 / 表尾对齐）**

## ⚠️ 易错点 / 难点

- **带头结点链表的遍历一律从 `head->next` 开始**：求长度、取首元结点都要跳过头结点，漏跳会把头结点算进去、长度多 1。
- **「共享后缀」的判据是「结点地址相同」，不是 `data` 相同**：两个链表的 `i` 字符可能分别位于不同结点上（那就不算共享）。因此比较时必须写 `p == q`（指针比较），写成 `p->data == q->data` 是**典型失分点**。
- **空间 O(1) 才是满分答案**：用辅助数组 / 栈把两条链全部结点存下来再倒序比较，虽然也能做对，但空间是 O(m+n)，不满足「时间上尽可能高效」之外隐含的空间要求。
- **表尾对齐时先走的必须是「较长」的那条链**：先走步数 = `|m − n|`；若符号取反会越过公共结点，导致漏判或指针越界。

## 🧩 易混对比

| A | B | 区别 |
|---|---|---|
| 比较结点地址 `p == q` | 比较结点数据 `p->data == q->data` | 求**公共结点/共享空间**必须比地址；比数据只能判断字符相同，无法判断是否共享存储 |
| 两条链「相交成 Y 形」 | 两条链「有相同字符」 | 前者公共点之后**所有结点地址全同**（共享物理空间）；后者只是数值巧合，物理上仍是两套结点 |
| 先求长度再对齐 | 同时遍历比较 | 前者需先走一趟求长度，但能保证同步段起点对齐，O(m+n) 时间 O(1) 空间；后者无法保证同步、会误判 |

## 🔢 解题模板：双指针找公共结点（表尾对齐）

> 适用：两条单链表（可带头结点）存在公共尾段，求**第一个公共结点**。这是 408 算法设计题的高频模板，2012 年真题即此型。

### ① 核心思想（三句话）

1. **本质**：公共后缀意味着从该结点起**地址完全相同**，问题等价于求两个相交单链表的**第一个交点**。
2. **难点**：两链表长度可能不同，若从各自的第一个结点同步后移，指针会错位，无法对齐比较。
3. **破法（表尾对齐）**：先各求长度 `m`、`n`，让**长链的指针先走 `|m − n|` 步**，此时两指针「距表尾的距离」相同；再同步每次走一步，**第一次 `p == q` 处就是公共结点**。

### ② 算法步骤

```text
1. 求长度 m = length(str1), n = length(str2)   // 都从 head->next 开始数
2. p = str1->next, q = str2->next
3. 对齐：令 diff = m - n
      若 diff > 0 ：p 先走 diff 步
      若 diff < 0 ：q 先走 -diff 步
4. 同步：while (p != NULL) { 若 p == q 返回 p；否则 p、q 各后移一步 }
5. 走到空仍未相遇 → 无公共后缀，返回 NULL
```

### ③ 参考代码（C 语言）

```c
typedef struct Node {
    char data;
    struct Node *next;
} ListNode, *LinkedList;

// 求链表长度（带头结点 → 从 head->next 起）
int getLength(LinkedList head) {
    int len = 0;
    ListNode *p = head->next;      // 跳过头结点
    while (p != NULL) { len++; p = p->next; }
    return len;
}

// 找共同后缀（公共结点）的起始位置
ListNode* findCommonSuffix(ListNode *str1, ListNode *str2) {
    int m = getLength(str1);
    int n = getLength(str2);

    ListNode *p = str1->next;      // 指向第一个链表的首元结点
    ListNode *q = str2->next;      // 指向第二个链表的首元结点

    // 1. 长链先走 |m - n| 步，实现「表尾对齐」
    int diff = m - n;
    if (diff > 0) {
        while (diff--) p = p->next;
    } else {
        while (diff++) q = q->next;   // diff 为负，逐步加到 0
    }

    // 2. 同步后移，找第一个地址相同的结点
    while (p != NULL) {
        if (p == q) return p;      // ★ 比较地址，不是 data
        p = p->next;
        q = q->next;
    }
    return NULL;                   // 无公共后缀
}
```

### ④ 复杂度

| 项 | 值 | 说明 |
|---|---|---|
| 时间 | **O(m + n)** | 求长度 O(m+n)，对齐 + 同步最多再 O(max(m,n))；两趟遍历 |
| 空间 | **O(1)** | 仅 3~4 个辅助指针，不随规模增长 |

### ⑤ 其他可行解法对比（考场按需选用）

| 解法 | 时间 | 空间 | 评价 |
|---|---|---|---|
| **双指针表尾对齐** | O(m+n) | **O(1)** | ✅ 本题标准答案，最优 |
| 栈 / 数组倒序比对 | O(m+n) | O(m+n) | 从尾部往前比，思路直观但空间不达标 |
| 哈希表存 str1 全部结点地址 | O(m+n) | O(m) | 可行但空间非 O(1) |
| 蛮力双重循环 | O(mn) | O(1) | 时间太低效，不满足要求 |

> 记忆：**「先量长短，长链抢跑，再齐步走，首次同址即交点。」**

### ⑥ 关联变式（同一「指针技巧」家族）

> 完整模板见 [[#🔢 解题模板：快慢指针（中点 / 判环 / 倒数第 k 个）]]。

- **求链表中点**：快慢指针（快走 2 步、慢走 1 步）。
- **判环 / 找入环点**：快慢指针相遇后，一指针回头结点，同步走再相遇处即入环点。
- **求单链表倒数第 k 个结点**：先让一个指针走 k 步，再同步走。
- **求两个链表的并集/差集**：仍需先对齐长度差。

## 🔢 解题模板：快慢指针（中点 / 判环 / 倒数第 k 个）

> 单链表算法设计题的另一大主力技巧。共同点：**先让某个指针多走一段，制造「长度差」，再用同步走或速度差解决问题**。416 真题的风格是「时间尽可能高效 + 不许改变链表结构 + 不许申请额外空间」，下列模板均满足 **O(n) 时间、O(1) 空间**。

### ① 求链表中点（找中间结点）

**思路**：`slow` 每次走 1 步、`fast` 每次走 2 步；`fast` 到表尾时 `slow` 恰在中间。

```c
// 返回中间结点（偶数个时返回前半段的最后一个结点）
ListNode* findMiddle(ListNode *head) {   // head 为头结点
    ListNode *slow = head->next, *fast = head->next;
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;        // 慢指针走 1 步
        fast = fast->next->next;  // 快指针走 2 步
    }
    return slow;
}
```

**结果规律（必须记准）**：

| 链长 n | `fast` 循环终止条件 | `slow` 落点 |
|---|---|---|
| 奇数 n=2k+1 | `fast->next == NULL` | 第 **k+1** 个结点，**正中间** |
| 偶数 n=2k | `fast == NULL` | 第 **k** 个结点，即**前半段的最后一个**（偏左） |

> ⚠️ 若想让偶数时取**后半段第一个**（偏右），把初值改为 `slow = head->next, fast = head->next` 但循环条件改成 `while (fast != NULL)` 或在 `fast->next != NULL` 时也前进一步——**两种约定都出现过，答按题意或注明约定**。

### ② 判环（是否有环）

**思路**：`slow` 走 1 步、`fast` 走 2 步，若存在环，二者必在环内**相遇**；若无环，`fast` 先到 `NULL`。

```c
int hasCycle(ListNode *head) {
    ListNode *slow = head->next, *fast = head->next;
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return 1;   // ★ 比较地址，相遇即有环
    }
    return 0;                          // 走到 NULL，无环
}
```

**为什么一定相遇**：两者速度差 1，`fast` 每轮把「与 `slow` 的距离」缩短 1，距离为整数，故必然缩到 0。

### ③ 找入环点（环的入口结点）

**经典结论（需会证）**：设头结点到入环点距离为 `a`，入环点到相遇点距离为 `b`，相遇点绕回入环点距离为 `c`（环长 `L = b + c`）。
相遇时 `fast` 走过 `a + b + kL`，`slow` 走过 `a + b`，且 `fast` 路程 = 2 × `slow` 路程：

```text
a + b + kL = 2(a + b)  ⟹  a = kL − b = (k−1)L + c
```

即：**从「头结点」和「相遇点」各出发一个指针（均每次 1 步），它们的相遇点就是入环点。**

```c
ListNode* findCycleEntry(ListNode *head) {
    ListNode *slow = head->next, *fast = head->next;
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) break;      // 先在环内相遇
    }
    if (fast == NULL || fast->next == NULL) return NULL;  // 无环

    slow = head->next;                // ★ 一指针回头结点
    while (slow != fast) {            // 两指针同速前进
        slow = slow->next;
        fast = fast->next;
    }
    return slow;                      // 相遇处即入环点
}
```

> 特例：`a = 0`（头结点后立即入环）时，情形等价于从头结点出发立刻相遇，即首元结点就是入环点。

### ④ 求单链表倒数第 k 个结点

**思路**：`p` 先走 `k` 步，`q` 再从首元出发；`p` 到 `NULL` 时 `q` 正好落在倒数第 `k` 个。

```c
ListNode* findKthFromEnd(ListNode *head, int k) {
    ListNode *p = head->next, *q = head->next;
    for (int i = 0; i < k && p != NULL; i++) p = p->next;  // p 先走 k 步
    if (p == NULL && k > 0) { /* 需判断：若 p 提前为空说明 k 超过表长 */ }
    while (p != NULL) { p = p->next; q = q->next; }        // 同步走
    return q;   // q 即倒数第 k 个（k 合法时）
}
```

> ⚠️ **边界**：求倒数第 `k+1` 个 = 求倒数第 k 个时让 `p` 先走 `k+1` 步；要删除倒数第 k 个，需知道其**前驱**，可先走 `k+1` 步或额外保存前驱指针。

### ⑤ 技巧家族总览（一张表记住「先走几步」）

| 问题 | 指针设置 | 关键结论 |
|---|---|---|
| 找中点 | 慢 1 步 / 快 2 步 | 快指针到尾时慢指针在中间 |
| 判环 | 慢 1 步 / 快 2 步 | 相遇即有环 |
| 找入环点 | 相遇后一指针回头结点，同速走 | 再相遇即入环点（`a = c` 推论） |
| 倒数第 k 个 | 一个先走 k 步，再同步 | 先走者到 NULL 时后走者到位 |
| 找公共结点 | 各求长，长链先走 \|m−n\| 步 | 首次同址即交点（见 [[#🔢 解题模板：双指针找公共结点（表尾对齐）]]） |
| 求两链并集/差集 | 先对齐长度差 | 差集时跳过公共段 |

> 一句话记忆：**「多点先走，制造差值；同速追上，交点自现。」**

### ⑥ 复杂度与易错点

- **复杂度**：以上全部 **时间 O(n)、空间 O(1)**，都是「一趟或两趟遍历 + 常数个指针」。
- **易错**：
  - 循环条件别写错：判环/找中点用 `fast != NULL && fast->next != NULL`（**两个条件缺一不可**，否则 `fast->next->next` 会空指针解引用）。
  - 快慢指针**比较的是地址**（`slow == fast`），不是 `data`。
  - 带头结点时初值从 `head->next` 开始，**别把头结点算进长度**。
  - 求倒数第 k 个要**判 k 是否大于表长**，否则会返回错误指针（未定义行为）。

## ❌ 错题

### 1. 找两个单词单链表共同后缀的起始位置（全国联考 2012 年 · 算法设计题）

- **题目**：假定采用带头结点的单链表保存单词，当两个单词有相同的后缀时，可共享相同的后缀存储空间。例如，`loading` 与 `being` 共享后缀 `ing`。设 `str1` 和 `str2` 分别指向两个单词所在单链表的头结点，结点结构为 `[ data | next ]`。请设计一个时间上尽可能高效的算法，找出由 `str1` 和 `str2` 所指两个链表**共同后缀的起始位置**（即字符 `i` 所在结点 `p`）。要求：(1) 给出算法的基本设计思想；(2) 用 C/C++/Java 描述算法，关键处给注释；(3) 说明时间复杂度。

  **存储结构**：
  - 链表 1（`str1`）：头结点 → `l → o → a → d → i → n → g`，末结点 `g` 的 `next` 为 `NULL`。
  - 链表 2（`str2`）：头结点 → `b → e`，结点 `e` 的 `next` **直接指向链表 1 中的结点 `i`**。
  - 公共后缀：`i → n → g` 三个结点**物理共享**，起始位置为结点 `i`（记为 `p`）。

- **正解过程**：

  **(1) 基本设计思想**
  1. 因共同后缀段**共享物理存储**，从起始结点往后，两链**结点地址逐一相同**；故问题转化为求**两个相交单链表的第一个公共结点**。
  2. **长度对齐**：先分别遍历两链求长度 `m`、`n`。将两指针重置到各自**首元结点**（`head->next`），令较长链的指针先走 `|m − n|` 步，使两指针**到表尾的距离相等**。
  3. **同步比较**：两指针每次同步后移一步，比较**指针地址**是否相等；**第一次 `p == q` 的结点即共同后缀起始位置**。
  4. 若走到 `NULL` 仍未相遇，说明两链无公共后缀，返回 `NULL`。

  **(2) 算法描述（C 语言）**：见上方 [[#🔢 解题模板：双指针找公共结点（表尾对齐）]] 的「③ 参考代码」，核心为 `getLength()` 求长 + 「长链先走 `|m−n|` 步」对齐 + `while (p != NULL) { if (p == q) return p; ... }` 同步查找。

  **(3) 复杂度**
  - **时间**：求长度 O(m+n)，对齐与同步最多再遍历一次较长链表 O(max(m,n))，合计 **O(m + n)**。
  - **空间**：只用 `p`、`q`、`diff` 等常数个辅助变量，**O(1)**。

- **易错提示**：
  - **必须比较地址 `p == q`**！写成 `p->data == q->data` 只能说明字符相同，不能说明共享存储——本题 `loading` 与 `being` 的 `n`、`g` 若存在于不同链上也满足字符相等，会误判。
  - **带头结点别忘 `head->next`**：求长度和取首元都要跳过头结点，否则长度多 1、对齐步数全错。
  - **先走的是长链**：`diff = m − n`，为正走 `p`、为负走 `q`（或统一用绝对值 + 判长短），方向别搞反。
  - **空间 O(1) 是得分点**：用数组/栈存全部结点再比较虽可行，但空间 O(m+n)，不满足「高效」要求。
