## 六、错题规范

### 6.1 错题笔记正文（**现行精简版**）

每条错题**只写三栏**：

```markdown
### 1. {题目标题}（{出处}）

- **题目**：{题干；程序段/公式用代码块或 LaTeX}
- **正确答案**：{答案，必要时标粗}
- **正解过程**：{分步骤编号，写清推理链}
```

**不写**「我的答案」「错因」「收获」——错因属于私人体会，不入库；结论性的教训一律上提到该笔记的 `⚠️ 易错点 / 难点` 区，作为长期考点留存。

## 八、写作红线

1. **不覆盖已有笔记。** 除非用户明确要求，任何自动化脚本、AI 操作都不得清空或重写既有内容，只做追加/定点替换。
2. **不写空话。** 禁止出现「很重要」「要熟练掌握」这类无信息量表述。
3. **占位符统一用 `⬜`。** 未填内容保持 `- ` 空行或 `⬜`，不要写「TODO」「待补充」等杂格式。
4. **公式用 LaTeX**：行内 `$...$`，独立成行 `$$...$$`（Obsidian 原生支持）。
5. **代码块标注语言**：` ```c `、` ```python `。
6. **表格必须对齐渲染**，表头分隔行不可省。
7. **一处一义**：同一结论不要在多个分区重复出现；重复即视为需要合并的信号。

## 九、操作规范（vault 操作 checklist）

Obsidian **正在运行**时，优先用 CLI（`obsidian` 命令），它会同步更新索引与链接缓存，避免直接改文件造成索引不一致：

```bash
obsidian read   path="03-数据结构/数据结构_08_排序.md"
obsidian create path="03-数据结构/新笔记.md" content="# 标题"
obsidian search query="归并排序"
obsidian property:set path="..." name="tags" value="..." type=list
```

四条铁律：

1. 一律用 **`path=`** 而非 `file=`（后者按名称模糊匹配，重名会命中错误笔记）。
2. `move` / `rename` **不会自动创建目标目录**，目标不存在直接报错。
3. 任务 `line=N` 是**含 frontmatter 的绝对行号**。
4. ⚠️ **`create` 对已存在路径不会覆盖**，而是**静默另建** `xxx 1.md`（实测确认）。想改正文只能用 `Edit` 定点替换，绝不能靠 `create` 重写。

### CLI 的能力边界

| 操作 | 用什么 |
|---|---|
| 读文件 / 列文件 / 搜全文 | CLI：`read` `files` `search` `search:context` |
| 建新文件 / 删文件 / 改名 / 移动 | CLI：`create` `delete` `rename` `move` |
| 改 frontmatter 属性 | CLI：`property:set` `property:remove` |
| 在**末尾/开头**追加内容 | CLI：`append` `prepend` |
| **在正文中间定点替换** | ❌ CLI 无此命令 → 用 `Edit` 工具，改完 `obsidian reload` |
| 查死链 / 孤立笔记 / 反链 | CLI：`unresolved` `orphans` `backlinks` `links` |

**每次改动收尾必做**：

```bash
obsidian reload            # 外部改动后同步索引
obsidian unresolved total  # 死链数，必须为 0
obsidian orphans total     # 孤立笔记，新笔记应已挂上主页
```

> CLI 不可用 / 库未打开时，可直接读写 `.md` 文件，但**改完必须**执行 `obsidian reload` 再校验。

> ⚠️ **表格会被 Obsidian 自动重排**（2026-09-11 实测）：库在 Obsidian 中打开并 reload 后，正文中所有 Markdown 表格的 `|` 会被自动对齐填充空格（如 `| A | B |` → `| A         | B           |`）。因此**对已有表格做 `Edit` 替换时，`old_text` 必须用不带多余空格的短语锚点**，或先 `read` 原文件取回填充后的真实文本；否则会因空格数不匹配而报「未找到待替换文本」。新建行时可写紧凑格式，reload 后会自动对齐。

| 角色 | 负责 | 不负责 |
|---|---|---|

### 11.2 动手前铁律

1. **先读本文件对应章节**，再动笔。与本文件冲突的操作一律不执行。
2. **以磁盘当前文件为准**，不拿上一轮会话的印象当真相。改之前 `read` 目标笔记（错题双写时连该科错题本一起读）。
3. **共享单点**（`README.md`、`00-主页.md`、各科 `错题本-*.md`）改前必重读全文。
4. **只追加或定点替换，不覆盖对方已写内容。** 同一结论已在另一分区出现 → 遵守 §8.7 一处一义，删重复的那侧，不两边都留。
5. **冲突停下问用户**，不默默改回去，不擅自纠正对方「看起来不像宪法」但用户可能已默许的写法。
6. 占位符一律 `⬜`；禁 `🔗`、`TODO`、`待补充` 及「收获 / 我的答案 / 错因」错题栏位。

### 11.3 不搞形式锁

两端不在同一进程，文件锁 / 「30 秒内被改过就重读」无法可靠执行。用 **重读** 代替锁：动手前读到的正文就是唯一真相。
